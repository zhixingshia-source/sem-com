============================================================
A. 一句话概述（项目目标）
============================================================
把多模态样本（图像/文本/音频/视频）压缩成可传输的语义载荷 `KToken-Reps`，再用 adapter 映射到目标语义空间（CLIP/CLAP 或 CoDi 条件 token），实现“语义检索 + 生成式重建（SD img2img / AudioLDM / CoDi）”，并输出可视化与评测结果（主线来自 `后续.pdf`；代码实现见 C/D）。

C. 运行流程（编号步骤 + 每步对应脚本/配置 + 输入输出）
============================================================

------------------------------------------------------------
C.1 项目目标/输入/输出（来自 `后续.pdf`）
------------------------------------------------------------
项目目标（PDF 主线提炼）：
- Stage‑1：把原始模态（image/text/audio/video）的 backbone token 序列压缩成 K 个语义 token（你在 PDF 里写成 “KToken‑Reps(32×512)” 之类）。
- Stage‑2：在 K tokens 上做选择/聚类/代表抽取，并压缩成可传输载荷（int8+scales 的 KToken‑Reps payload）。
- Stage‑3：训练 adapter，把载荷映射到目标语义空间（例如 CLIP image embedding），用于检索；或映射到生成模型条件空间，用于生成式重建（SD img2img / AudioLDM / CoDi）。

输入（按主线）：
- 原始数据：图像（可能多帧/多视角），文本 caption，音频 wav，视频 mp4（按数据集可缺省某些模态）。
- 训练/推理工件：Stage‑1 ckpt（extractor）、Stage‑2 payload、语义库 sem_db、Stage‑3 adapter ckpt、生成模型权重（SD/AudioLDM/CoDi）。

输出（按主线）：
- Stage‑1：`snapshots/*.pth`（extractor 权重）
- Stage‑2：`comprehensive_output/payloads/<safe_stem>_{payload.json,reps.pt,members.json,stats.json}`
- Stage‑3：`runs/.../adapter_*.pth`（或任意你指定的输出目录）
- 检索：`--outdir/<stem>_topK.png`（拼图）+ 控制台 top‑k 列表
- 生成：`--outdir/<stem>_gen_*.png`（图像）或 `<stem>_recon.wav`（音频）或 `frames_cfg_*/*.png`（视频帧）
- 评估：`comprehensive_output/eval/<stem>_eval.json` + `<stem>_coverage_curve.png`

C.2 数据布局（代码侧明确约定）
------------------------------------------------------------
核心约定（`second_ssss.py` / `first_train_multiview_align.py` / `stage1_reworked.py` 等共用）：
- 数据根目录：默认 `./data`；或通过 `--data_root <DIR>` 覆盖（至少 `first_train_multiview_align.py`、`stage1_dupsafe.py`、`second_ssss.py` 支持）。
- 子目录固定为（注意拼写）：`image/`、`text/`、`audio/`、`vedio/`。
- 图像命名：多处脚本采用 “stem_0001.jpg” 或 COCO 风格 “coco_000001_0001.jpg”；
  `second_ssss.py` 与 `build_image_sem_db_(11-22).py` 均按 “去掉最后一个 _XXXX” 来得到 stem。

Stage‑2 输出命名（`second_ssss.py` 明确实现）：
- 对每个样本 stem（可能包含 `/`，如 Clotho 的 `dev/clotho_dev_00001`），输出文件名会先做扁平化：
  `safe_st = st.replace(\"/\", \"_\")`
  因此最终文件名是：
  - `comprehensive_output/payloads/<safe_st>_payload.json`
  - `comprehensive_output/payloads/<safe_st>_reps.pt`
  - `comprehensive_output/payloads/<safe_st>_members.json`
  - `comprehensive_output/payloads/<safe_st>_stats.json`

C.3 Stage‑1（训练 extractor：backbone tokens → K tokens）
------------------------------------------------------------
对应 PDF：Stage‑1（KToken‑Reps 的来源）。

推荐脚本（支持 `--data_root`，更容易复现）：
- `first_train_multiview_align.py`
  - 关键参数（节选，见 argparse）：
    --data_root：数据根目录（默认 ./data）
    --codi_root/--codi_ckpt：CoDi 代码与 checkpoints（可覆盖默认 Linux 路径）
    --steps：训练步数
    --K / --K_text / --K_image / --K_audio：每模态 K
    --adapter / --adapter_depth / --adapter_width / --adapter_heads：对齐前的可学习 adapter head（可选）
    --save_every：保存间隔（输出到 `snapshots/`）
  - 输入：`<data_root>/{image,text,audio,vedio}` + `i-Code-V3/checkpoints/CoDi_encoders.pth`
  - 输出：`snapshots/*.pth`（extractor ckpt；供 Stage‑2 使用）

其它 Stage‑1 脚本（同类，不一一推荐）：
- `stage1_reworked.py`：更激进的反塌缩损失组合（slot usage/entropy/infonce 等），但脚本未看到 `--data_root` 参数，默认只认 `./data`。
- `stage1_dupsafe.py`：也支持 `--data_root`，且脚本尾部对 “text+audio 成对样本” 有专门采集逻辑（更偏 Clotho）。


------------------------------------------------------------
C.4 Stage‑2（生成 KToken‑Reps payload：选择/聚类/量化/打包）
------------------------------------------------------------
对应 PDF：Stage‑2（把 K tokens 压缩成可传输载荷）。

脚本：`second_ssss.py`
关键参数（argparse）：
- 数据与样本：
  --data_root：数据根目录（默认 ./data）
  --stem：处理单个 stem
  --all：处理所有 “至少 2 个模态存在” 的 stem（text+image 即满足）
- 选择/聚类：
  --sel：selection threshold（默认 0.8）
  --clu：cluster threshold（默认 0.8）
  --floor：每模态最少保留 token 数
  --topk_per_modality：阈值后再取 Top‑K
  --rep_per_cluster：每簇选多少个代表（>=1）
- 预算裁剪：
  --budget：最多传多少个代表 token（0=不限）
  --budget_strategy：by_cluster_size / uniform / none
- ckpt/输出：
  --ckpt：Stage‑1 输出的 extractor ckpt（默认 `snapshots/step_0300.pth`）
  --out：输出目录（默认 `comprehensive_output/payloads`）
- 可选 adapter（对 reps 再变换后再选/聚类）：
  --adapter：identity/mlp/xattn
  --adapter_depth/--adapter_width/--adapter_heads
  --adapter_ckpt：可选加载 adapter 的 state_dict
- 编码取帧/音频截取：
  --img_take：每个 stem 取多少张图像帧
  --aud_seconds：音频截取长度

输入：
- Stage‑1 ckpt：`--ckpt snapshots/step_XXXX.pth`
- CoDi encoders：`i-Code-V3/checkpoints/CoDi_encoders.pth`（脚本内部加载）
- 数据：`--data_root` 下的 `image/text/audio/vedio`（至少 2 个模态存在才会进 `--all`）

输出（对每个 stem，注意 safe_st 替换 `/` 为 `_`）：
- `comprehensive_output/payloads/<safe_st>_payload.json`
  - 结构要点：
    kind=KToken-Reps
    n_tokens=N, dim=D（通常 D=512）
    dtype=int8, encoding=zlib+base64
    scales: List[float]（每 token 一个 scale）
    data: base64(zlib(int8[N*D]))
    metadata: 包含 rep_members / cluster_sizes 等
- `comprehensive_output/payloads/<safe_st>_reps.pt`（代表 token 的 float32 Tensor）
- `comprehensive_output/payloads/<safe_st>_members.json` / `<safe_st>_stats.json`


------------------------------------------------------------
C.5 Stage‑3（训练/使用 adapter：payload → 语义空间/生成条件）
------------------------------------------------------------
对应 PDF：Stage‑3（adapter），以及后续 retrieval/generation。

1) 图像检索空间（CLIP image embedding）
- 训练：`kreps2clip_train.py`
  - 输入：
    --payload_root：包含 `*_payload.json` 的目录（注意：此脚本用 `glob(\"*_payload.json\")`，只扫一层，不递归）
    --image_root：图像目录（按 stem 配对；默认认为 `coco_000001_0001.jpg` 属于 stem `coco_000001`）
  - 输出：`--outdir/adapter_clip_best.pth`（以及按步保存的 ckpt）
    - ckpt 字段（脚本保存）：
      state_dict / d_in / d_out / x_mean / x_std / max_tokens / clip_model
  - 关键参数：
    --clip_model（必须与 build_image_sem_db 用同一个，否则维度/空间不一致）
    --max_tokens（adapter 输入固定维度 = max_tokens * D_token）
    --steps / --batch_size / --hidden / --layers / --lr / --weight_decay
    --lambda_mse / --lambda_cos（损失权重）

- 构建语义库：`build_image_sem_db_(11-22).py`
  - 输入：--image_root + --clip_model
  - 输出：--out_path（`.pt`，含 stems+embeds）

- 推理检索：`kreps2sem_infer_(11-22).py`
  - 输入：--payload_root、--adapter_ckpt、--sem_db、--image_root
  - 输出：--outdir 下 `<stem>_topK.png`
  - 关键一致性检查：脚本会检查 `adapter d_out` == `sem_db embeds dim`，不一致会直接报错。

2) 生成（图像：SD img2img）
- `kreps2gen_img2img_(11-26).py`
  - 输入：与 `kreps2sem_infer` 类似，再加 `--text_root`（读 caption 拼 prompt）与 `--sd_model` 等。
  - 输出：`--outdir` 下保存参考图、生成图、并排对比图（文件名见脚本头 docstring）。

3) 音频语义空间（CoDi CLAP → AudioLDM）
- 训练：`kreps2clap_train.py`（payload → CLAP embedding）
  - 注意：此脚本也用 `glob(\"*_payload.json\")`（只扫一层）。
  - Clotho 的原始 stem 可能含 `/`，但 Stage‑2 输出已用 `safe_st=replace(\"/\",\"_\")` 扁平化，脚本内部按规则还原去找 wav。

- 推理重建：`kreps2gen_audio_recon.py`（payload → adapter → CLAP embedding → AudioLDMPipeline 生成 wav）
  - 输出：`--outdir/<stem>_recon.wav`（脚本支持 `--all` 批量，对 payload_root 用 `rglob` 递归扫）

- 评测：`eval_audio_recon.py`（对齐原 wav 与 recon wav，算 MSE/SNR/log-mel MSE/cos）

4) CoDi 条件 tokens 生成（示例：视频）
- `train_adapter_semcom.py`：训练 reps → `(1,L,768)` 的 adapter ckpt（保存 ctx_len/ctx_dim）
- `gen_with_adapter.py`：payload/reps → adapter → cond tokens → CoDi sampler.sample → 输出帧/PNG/GIF

C.6 PDF 与代码不一致/冲突点（并给出更可信解释）
------------------------------------------------------------
1) Stage 编号口径不完全一致
- PDF 里写的 “Stage‑1/2/3” 与代码脚本名基本能对上，但部分脚本的 docstring 会把“训练 adapter”称作某个阶段（例如你可能把它叫 Stage‑2/3）。
- 更可信解释：以 `second_ssss.py` docstring 的定义为准：它明确写“Stage‑2：Token Selection → ... → payload”，而 adapter 训练属于其后续（这里统一称 Stage‑3）。

2) PDF 中出现的“占位脚本名”（代码里不存在）
- `后续.pdf` 中可见类似 `build_audio_sem_db_(MM-DD).py`、`kreps2audio_train_(MM-DD).py` 等名字（MM-DD 是占位日期）。
- 更可信解释：这是你规划中的脚本命名模板；当前仓库里对应功能可能以其它文件名实现，例如：
  - 音频 text+audio sem_db：`build_clotho_text_audio_sem_db.py`
  - 音频 adapter：`kreps2clap_train.py`、`kreps2audioldm_train.py`

3) `semantic_comm/` demo 与主线脚本体系是两套风格
- `semantic_comm/scripts/run_pipeline.sh` 试图用 `--exp configs/experiment.yaml` 驱动；
  但 `semantic_comm/src/pipelines/semantic_comm_pipeline.py` 目前主要是硬编码流程与开关（不解析 exp），且默认开关可能导致运行到未初始化的分支。
- 更可信解释：`semantic_comm/` 是单独 demo/草稿，与 PDF 主线（Stage‑1/2/3 的顶层脚本）并行存在；写论文/跑主实验建议以顶层脚本链路为准。

4) 数据压缩包当前看起来不完整
- 目录里有 `data_coco.tar.gz`/`data_clotho.tar.gz`，但 `tar -tf` 会报 “Truncated input file”。
- 更可信解释：压缩包是截断/未完整下载的，需要重新获取；否则解包/训练/推理都会缺文件。

F. 常见问题与排错（具体到文件/参数/路径）
============================================================

1) `snapshots/` / `comprehensive_output/` / `runs/` 等目录不存在
- 现象：脚本报找不到 ckpt/payload/sem_db，或输出路径不存在。
- 处理：
  - `second_ssss.py` 会对 `--out` 自动 `mkdir(parents=True)`，但前置的 `--ckpt` 必须存在。
  - `kreps2clip_train.py`/`build_image_sem_db_(11-22).py` 会对 `--outdir/--out_path` 创建父目录，但输入目录必须存在。

2) 数据目录拼写问题：`vedio` 不是 `video`
- 现象：明明有视频文件但脚本认为没有（或 `--all` 找不到样本）。
- 处理：把目录命名为 `vedio/`（或改脚本，但你当前要求不修改文件）。

3) stem 命名不一致导致配对失败（最常见）
- 关键规则（代码）：
  - `second_ssss.py`：图像 `*_*.jpg` → stem = “去掉最后一个 _XXXX”
  - `build_image_sem_db_(11-22).py`：同上（COCO 风格匹配）
  - `kreps2clip_train.py`：同上（按 stem 配对 payload 与 image）
  - `text2clip_fromtxt_(11-23).py`：caption 文件必须是 `text_root/<stem>.txt`
- 处理：统一你的文件命名与 text 文件名，确保 stem 完全一致。

4) payload 文件名（含 `/`）的问题
- Stage‑2 已做扁平化：`safe_st = st.replace(\"/\",\"_\")`（见 `second_ssss.py`）
- 影响：如果你的原始 stem 是 `dev/clotho_dev_00001`，payload 文件名会是 `dev_clotho_dev_00001_payload.json`。
  这与 `kreps2clap_train.py`/`kreps2audioldm_train.py` 的注释假设一致。

5) transformers/CoDi tokenizer 兼容性报错（`get_vocab` / `encoder`）
- 现象：AttributeError: tokenizer has no attribute encoder 等。
- 处理：
  - 多个脚本自带 `_patch_codi_clip_tokenizer()`：确保你使用的是这些脚本入口，而不是直接从其它地方 import 未 patch 的 CoDi tokenizer。
  - 若仍失败：尝试匹配 `transformers>=4.40.0`（见 `semantic_comm/requirements.txt`），并确保 CoDi 代码版本与之相容。

6) sem_db 维度与 adapter 输出不一致
- 现象：`kreps2sem_infer_(11-22).py` 报 `dimension mismatch: adapter d_out=... vs sem_db D=...`
- 处理：保证：
  - `kreps2clip_train.py --clip_model X`
  - `build_image_sem_db_(11-22).py --clip_model X`
  两者的 CLIP 模型名一致（同一 embedding 空间、同一维度）。

7) HuggingFace/模型下载导致“卡住/失败”
- 现象：首次运行 CLIP/SD/AudioLDM 时长时间等待或下载失败。
- 处理：提前缓存或改用本地模型路径；设置 `HF_HOME/TRANSFORMERS_CACHE`；离线环境避免直接跑生成脚本。

8) `data_coco.tar.gz` / `data_clotho.tar.gz` 解包报错
- 现象：`tar` 报 `Truncated input file`
- 处理：压缩包可能不完整，重新下载/重新打包；否则数据缺失会导致训练/推理失败。
